QuerySage DEPN Validation Supplementary Material
==================================================

This is the data referenced in the manuscript's Data Availability
declaration and Section 8.4: the real execution plans used to validate
DEPN (the Dialect-Neutral Execution Plan Normalizer), and the scripts that
generated, captured, and evaluated them. It accompanies
QuerySage_AIR_Springer_submission_Final.docx.

RESULT

DEPN assigned the correct canonical node type (Table 3 of the manuscript)
in 94.7% of cases: 1,867 of 1,972 plan nodes, drawn from 828 real
PostgreSQL 16 EXPLAIN (FORMAT JSON) plans. The one node type it does not
cover is the internal build-side node PostgreSQL inserts under a hash
join ("Hash"), which Table 3 does not list as a canonical type in its own
right -- 105 occurrences, all the unmapped nodes in this run.

SCOPE, STATED PLAINLY

This validates DEPN against one engine: PostgreSQL 16, installed
and run. Table 3 also specifies mappings for Oracle 21c and MySQL 8.0. Their columns in Table 3 remain a documented design target.

DATA

The schema is TPC-H-shaped (the standard eight tables: region, nation,
supplier, customer, part, partsupp, orders, lineitem) but the data is
synthetic, generated by scripts/generate_data.py rather than the official
TPC-H dbgen tool -- real foreign-key integrity, realistic date ranges and
skew, but not the official benchmark dataset. Scale is approximately 1x
(~600,000 lineitem rows). This choice was made for practicality (dbgen
requires compiling a separate C toolkit) and is disclosed here rather
than implied to be the official TPC-H dataset.

828 queries (scripts/generate_queries.py, output in queries.sql) were
generated to exercise all ten of Table 3's canonical node types: plain
and indexed scans, two- and three-way joins across both hash and nested-
loop strategies, explicit sorts, grouped aggregates, derived-table and
IN-subqueries, and multi-table queries mixing several of these at once.

FILES

  queries.sql                    the 828 generated queries, one per line
  postgres_plans.json             the raw captured EXPLAIN (FORMAT JSON)
                                   output for every query -- the actual
                                   plan data DEPN was evaluated against
  depn_validation_plans.csv       one row per plan: engine, query (first
                                   200 chars), node counts, how many
                                   normalized vs. not
  depn_validation_summary.json    the aggregate result, the Oracle/MySQL
                                   scope notes above in machine-readable
                                   form, and the unmapped-node-type tally
  scripts/
    sql/schema_postgres.sql       the TPC-H-shaped schema, Postgres dialect
    sql/schema_mysql.sql          the same schema, MySQL dialect (unused
                                   in this run, kept for whoever gets
                                   MySQL running and wants to extend this)
    generate_data.py              synthetic data generator (seeded,
                                   reproducible: random.seed(20261026))
    generate_queries.py           the 828-query generator
    load_and_run.py                loads the schema+data and captures
                                   EXPLAIN plans from a live engine
    depn.py                       the actual DEPN implementation: the
                                   Table 3 mapping and the plan-tree
                                   walkers for Postgres and MySQL
    evaluate.py                    runs depn.py against the captured
                                   plans and produces the two files above

REPRODUCING THIS

    createdb depn_exp
    python scripts/generate_data.py 1.0
    python scripts/generate_queries.py > queries.sql
    python scripts/load_and_run.py --engine postgres --load \
        --pg-dsn "host=localhost dbname=depn_exp"
    python scripts/evaluate.py

Requires psycopg2-binary and pymysql (for the MySQL path, once an
instance is reachable).
